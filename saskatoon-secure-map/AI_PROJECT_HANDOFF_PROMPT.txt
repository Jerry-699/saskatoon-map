I have a private web app called Saskatoon Block Finder. Please preserve the existing working features and security when modifying it.

TECH STACK / DEPLOYMENT
- Next.js app deployed on Vercel.
- GitHub repo: Jerry-699/saskatoon-map.
- Vercel Root Directory must remain: saskatoon-secure-map.
- Supabase handles authentication and database.
- Users sign up, then an admin approves them before map access. Admins can approve, revoke/pending, block/deny access, and unblock users.
- Blocked/unapproved users must not be able to access protected map/API data.
- Forgot-password/reset-password flow exists.

MAP
- Mobile-first full-screen MapLibre map using OpenStreetMap raster tiles.
- Saskatoon block/address lookup by tapping the map.
- Accurate GPS arrow, compass, zoom controls, and a 3-dot collapsible menu.
- Drive mode follows GPS without automatically changing the user's chosen zoom.
- While driving there is a Follow Lock button: locked means map follows the GPS arrow; unlocked means recording/GPS continues but the user can freely pan/inspect the map without being pulled back.
- Day/night is automatic: dark from 7:00 PM to 7:00 AM, light from 7:00 AM to 7:00 PM. The user can manually override with the Day/Night button; the override lasts until the next 7 AM or 7 PM boundary.
- No voice navigation and no destination/address navigation feature.

ROUTES
- Admin-managed GPX routes are stored in Supabase and visible to approved users. Admin can upload/delete/reorder them.
- There are NO hard-coded built-in routes.
- Selected/saved planned routes display in RED.
- Route Drive lets a user select an existing route, keeps that red planned route visible, and records the actual driven trace live in BLUE. Pause/resume starts a new trace segment so there is no straight-line gap.
- A user can also press “Make New Route” without selecting an existing route. It records their actual GPS path live in BLUE. When they stop, they can save it privately. After saving it displays in RED.
- Private saved driven routes are stored in Supabase table public.driven_routes and protected with RLS so only the owner can read/create/delete their routes. They appear in the route selector with a lock symbol and can be driven later.

FIRE HYDRANTS
- City hydrants use City of Saskatoon ArcGIS service Prod_SaskatoonWater FeatureServer layer 5.
- Admin-added missing hydrants are stored separately in Supabase manual_hydrants and merged into map display.
- Admin panel includes a hydrant picker to add/delete manual hydrants.

LATEST RECOVERY / PHONE BEHAVIOR
- The map requests the browser Screen Wake Lock API while the map page is visible, and retries when the tab becomes visible or the user taps the page. This is best-effort: the OS/browser may still release it in low-power/background situations.
- Unfinished route recording is crash/close resistant. The client stores the latest draft locally immediately and also syncs it to the signed-in user's Supabase drive_drafts row.
- If the page is closed while recording, reopening/logging back in automatically restores the route and starts a NEW segment before recording resumes, so the closed-window gap is never connected by a fake straight line.
- If recording was stopped but not saved, reopening shows the unsaved route in BLUE with Save and Discard options.
- After a private route is saved, it is shown RED and only that user can see it.
- SQL required once: supabase/drive-draft-recovery.sql (in addition to driven-routes.sql).

SECURITY / AUTH FIXES (2026-09-02)
- After a successful password reset, app/actions.ts explicitly calls supabase.auth.signOut() before redirecting to /login, preventing a stale recovery session.
- Access polling redirects with window.location.replace() instead of window.location.href so blocked/unapproved users cannot use browser Back to temporarily revisit the map.


LATEST ROUTE RECOVERY RELIABILITY FIX:
- Active/unsaved drive drafts are saved locally immediately and synchronized to Supabase at least every 5 seconds while recording (throttled, not debounced).
- Clicking Sign out while a route is active waits for the latest draft to be saved to Supabase before logging out.
- This prevents the previous bug where a continuously moving GPS could keep resetting the old 8-second debounce and therefore never persist the latest route server-side.
- Recovery should work after a long logout and on another device after logging into the same account, provided the drive_drafts SQL table exists and the save request succeeds.
